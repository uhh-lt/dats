# ADR 0008: The artefact system owns planning and availability

**Date:** 2026-11-13

Step planning, step runs, step statuses and the availability of artefacts live in `systems/artefact_system`, which knows artefacts and pipeline steps and never imports the feature system or a module; the feature system keeps the features, their statuses and the actions Enable, Complete and Disable, and talks to it in artefacts only. Enable and Complete pass the artefacts of the feature to `ArtefactService.compute`, which stores a pending artefact computation (computation id to its fixed artefact set, `project.artefact_computations`) and plans in batches in a background job; the feature status reads `ArtefactService.read_availability` with one artefact set per feature; Disable calls nothing; the upload passes the artefact demand of the project, read under the project share lock by `FeatureService.read_artefact_demand`, to `ArtefactService.plan_document`. This is possible because image captions are a core artefact: every document has text, so no planning question depends on the other enabled features, and a computation never re-reads them per batch. The entry-point jobs start their followers themselves, so the step runs know no entry point, and the layering lint has no exemption.

This supersedes in part ADR 0003 (the artefact service owns the planning writes and the pending computations, the feature service owns `project.enabled_features`; each has its private statements), ADR 0005 (the background work is the artefact computation, keyed by its id with its artefacts, and a feature reads Computing while a pending computation computes one of its artefacts, also a feature that only shares the artefact) and ADR 0007 (`FeatureService` carries out the actions; the feature system imports no module).

We rejected keeping the activation job in the feature system with a per-batch planning call: five public calls instead of four, two with a lock precondition nobody can check, and more job hooks whose order becomes behaviour. We rejected an opaque key per feature in the pending computations: the artefact system would store a value it does not understand.
