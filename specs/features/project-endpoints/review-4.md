## 2. To fix before the merge

### 1. The "Recents" list of memos lost its limit of 10

- **Where**: `frontend/src/core/memo/api/memoQueries.ts:65`.
- **What**: the old call `getRecentMemos({ projectId })` used the backend default `limit: int = 10` of `GET /memos/recent`. The new call `MemosService.getByProject({ projectId, recent: true })` sends no `limit`, and the new default is `None` (`core/memo/memo_endpoint.py:65`, `core/memo/memo_crud.py:178`).
- **Why**: the sidebar (`frontend/src/features/memo-workspace/views/main/_components/MemoWorkspaceSidebar.tsx:73`) now loads every memo the user ever opened in the project. `crud_memo.update_recent` never trims the table.
- **Fix**: pass `limit: 10` in the query function.
- **Confidence**: high (old and new path read end to end).

### 2. `GET /memos` has no defined order, and `limit` cuts an unordered result

- **Where**: `core/memo/memo_crud.py:141-180`.
- **What**: `ORDER BY` is only set when `opened_by_user_id` is given. The plain list and every filtered list have none. `limit` is applied in every case. The recent order `last_opened.desc()` has no tie-breaker.
- **Why**: rule 4, "lists in a defined order". The route is new in this shape (it merged `GET /memos/recent` into `GET /memos`), and commit `92065e1b9` fixed exactly this for the other list reads. `limit` is also not validated: a negative value reaches PostgreSQL.
- **Fix**: `order_by(MemoORM.id)` as the default, `last_opened.desc(), MemoORM.id` for recent, and `limit: int | None = Query(None, ge=1)`.
- **Confidence**: high.

### 3. A filter on a removed member breaks the export (regression of the user-id fix)

- **Where**: `core/user/user_crud.py:81-101` (`read_by_project_and_ids` raises `NoSuchElementError`), called from the `resolve_ids` of the six `*_columns.py`, reached through `systems/search_system/filtering.py:159,173,201` from `modules/eximport/timeline_analysis/timeline_analysis_transformations.py:69`.
- **What**: `DELETE /members/{user_id}` only removes the link (`core/project/project_crud.py:75-87`). The annotations of the user stay, and so does a saved timeline analysis filter on the user id. Since `b65c17af7` the export of such an analysis (`SELECTED_TIMELINE_ANALYSES`, `ALL_TIMELINE_ANALYSES`, `ALL_DATA`) raises in the worker. Before the fix the id resolved to the email.
- **Why**: a project with a former member can no longer be exported as a whole.
- **Fix**: resolve against every user that has rows in the project (members, virtual users, users with an annotation document or memo there), or keep an unresolvable user id out of the exported filter instead of raising. Add a test with a removed member.
- **Confidence**: medium. The code path was read end to end. It was not run.

#### Unclear (the rule needs judgement; both readings)

1. **`POST /concept-over-time-analyses/{cota_id}/refine`** starts a job outside `/jobs`. Reading A: rule 5.1 has no such case, so it is a deviation. Reading B: a verb on one item (rule 2.3) that starts a job (rule 1). It also sets `last_refinement_job_id` and answers the COTA without a websocket event, while `POST /jobs/perspectives` emits `ASPECT_UPDATED` for the same kind of write.
2. **`POST /doc-processing/recompute`, `/retry` and `POST /features/{feature}/complete`** start jobs outside `/jobs` and work on no single item. Reading A: deviations from 5.1. Reading B: like `POST /doc-processing/upload`, which the rules file uses as its example of a verb below a namespace.
3. **The three exports** (`POST /agreements/export`, `POST /word-frequencies/export`, `POST …/runs/{run_id}/export-log`) write a file and answer its URL. `crud_export_file.write` also deletes expired exports. Reading A: not "stores nothing". Reading B: a computation whose result is a temporary file (`findings.md` section 12 calls this "does something", hence the verb).
4. **`POST /authentication/logout` and `/refresh-access`** revoke, delete and create refresh tokens. Reading A: they change stored state. Reading B: session actions that go with the kept `POST /login`.
5. **`POST /rag/answer`** appends to a chat session held in process memory. Reading A: not stateless. Reading B: nothing is stored in a data store.
6. **`PATCH /features/{feature}/enable`** changes state and starts the artefact computation. **`PATCH …/accept-labels` and `…/revert-labels`** change state, take search input and answer a computed visualization. Each is a `PATCH` and a `POST` in one request.
7. **`PATCH …/recompute`, `…/refresh-scores`, `…/reset`, `PATCH /memos/{memo_id}/mark-recent`** (an upsert that may insert), **`PUT /perspectives/aspects`** and **`PUT /experiments/{experiment_id}/runs`** (create a row and start a job): the method fits the stored effect; a second effect comes with it.
